# PROPP GRAMMAR v46
# ============================================================================
# The grammar of SynthesizedProppGrammar, built from v44 one step at a
# time. v44's language is the invariant and v43 a source of shapes: each
# step is labeled language-preserving or language-changing, and its tests
# are frozen in StepTests.txt before it is built. Each step is tagged in
# git; run the tests for the current step with
#
#   python runSteps.py N
#
# STATE: STEP 8. THE GRAMMAR IS CONTEXT-FREE AND LL(1), with no conflict.
# Step 1 regrouped v44 into the pairs and groups Propp names. It ADDED NO
# STRING: the move layer is v44's, symbol for symbol, which the tests
# prove rather than assert. What it added is STRUCTURE. v44 is a flat slot
# sequence, so every move-string has one shape; here each move parses into
# constituents a meaning can attach to. In the terms of finding FO, the
# weak generative capacity is unchanged and the strong generative
# capacity is added.
# Step 2 adds the tale above the move: an optional initial situation, the
# preparatory section, then one or more moves in sequence. It CHANGES THE
# LANGUAGE, adding tale-level strings, and leaves the move layer as it
# was.
# Step 3 builds two licenses of p.108 into the move: T may stand
# anywhere, and recognition, exposure, marriage and punishment exchange
# among themselves. It CHANGES THE MOVE LAYER, which now accepts exactly
# the language of Step3Spec.txt, a flat statement of v44 with those two
# licenses, written before the step was built.
# Step 4 builds in the three licenses left: the domestic agent before the
# departure (p.108), the fight after pursuit (p.107) and the humorous
# inversion of rescue and pursuit (p.147). It CHANGES THE MOVE LAYER, only
# adding strings. Over the 84 resolved move-strings it accepts 80, and
# the four it refuses are the genuine counterexamples. It costs a second
# LL(1) conflict, on F.
# Step 5 removes the J conflict by letting the task-run J come only after
# a task, the repair v44's own comment names. It CHANGES THE MOVE LAYER,
# only removing strings, all of them task-run J's with no task, and the
# corpus verdict stays 80 of 84. The F conflict stays: no lookahead
# removes it while the father's agent and the donor's are separate
# groups, and the choice is the owner's.
# Step 6, by the owner's decision, merges the F groups: an F after the
# donor's test is the tested agent, and every other F, the father's gift
# included, is the untested agent. The token before each F now decides
# its group, and the F conflict is gone. It CHANGES THE MOVE LAYER, only
# adding strings: an untested agent may now be followed by a test, which
# the narrow reading of step 4 refused. The corpus stays 80 of 84.
# Step 7 embeds moves: after any function a move may pause for another
# move, bracketed ⟨ ... ⟩, to any depth. The grammar is no longer regular,
# and is still LL(1). With the pause removed it is exactly step 6. Over
# the 45 whole tales of embedCorpus.py's derivation it accepts 41, the
# four refused being the tales that hold the four genuine counterexamples.
# Step 8 adds two more of p.93's methods of combining moves, at the tale
# level: a common ending shared by two moves (method 5) and two seekers
# parting at a road marker into two branch moves (method 6), written with
# Propp's own signs } < Y. With both removed it is exactly step 7, and it
# is still LL(1); the tale corpus stays 41 of 45.
#
# Notation is v44's:
#   A = x    a production: the nonterminal A is defined as x.
#   'x'      a terminal, one of Propp's function symbols.
#   [X]      optional.     {X}  zero or more.
#   X Y      concatenation.  X | Y  alternation.
#   # ...    a comment to end of line; not part of the grammar.
# The ';' an EBNF compiler expects is omitted for readability, as in v44.
# ============================================================================


# ----------------------------------------------------------------------------
# NAMING, borrowed from v43
# ----------------------------------------------------------------------------
#   lowerCamelCase  Propp names it: a function, by his definition in
#                   Ch. III, or a group he names in his own text.
#   UpperCamelCase  Editorial: a grouping this grammar makes and names.
#                   Where v43 had a name for the same span, it is reused.
# Every group, lower or upper, cites the page that warrants the grouping
# where Propp gives one. An upper-case group with no page is a grouping
# for reading only, and claims nothing about Propp.


# ----------------------------------------------------------------------------
# THE TALE  (step 2)
# ----------------------------------------------------------------------------
# p.92: morphologically, a tale is any development proceeding from
# villainy or lack; each new villainy or lack creates a new move, and
# moves may follow one another. So a tale holds at least one move, and a
# preparatory section with no move is not a tale.
#
# MOVES ARE SEQUENTIAL ONLY, for now. p.92 also lets moves interweave;
# interruption is a later step.
#
# THE PREPARATORY SECTION STANDS BEFORE THE FIRST MOVE ONLY, by the
# owner's decision, because Propp never places one before a later move.
# p.86 says second moves begin with a given situation, meaning who stands
# where, and Appendix I Table VI, p.125, begins the second move from a new
# villainy. Admitting one later would move preparatorySection inside the
# repetition.
#
# THE INITIAL SITUATION, α, is not a function and precedes the functions
# (p.25). It takes [ ] and not { }: it is optional and it is not
# repeated. It stands at the beginning of the tale only, by the owner's
# reading of p.86's "given situation" as the tale's initial situation.
# Admitting [initialSituation] before a later move would be a small edit.
#
# NO EXCLUSION IS ENCODED among the preparatory functions. p.108 observes
# that all seven never occur within one tale; by the owner's decision the
# grammar does not forbid it.
#
# MOVES ARE SEPARATED BY '/', by the owner's decision. A move may open on
# B (p.37), and B may also follow an opener inside a move, so without a
# separator a string such as A B C parsed two ways: one move, villainy
# then mediation then counteraction, or the move A followed by the move
# B C. That was a true ambiguity and an LL(1) conflict on B. With the
# separator, A B C is one move and A / B C is two, and J is again the
# only conflict. The separator is editorial, not Propp's symbol, but it
# follows his layout: Appendix III prints each move on its own row. No
# corpus tale was ambiguous without it; the one later move opened on B,
# 133 II, follows a move ending D E F.

tale                = [initialSituation] preparatorySection move
                      LaterMoves

# --- how the moves of a tale combine: p.93, methods 1, 5 and 6 (step 8) ---
# p.93 lists six methods of combining moves. Methods 2 and 3, interruption,
# live inside the move (InterruptingMove). Method 1, one move after
# another, is the repetition below. Methods 5 and 6 are tale-level:
#   METHOD 5: "Two moves may have a common ending." Propp draws one closing
#   brace across both moves with the ending to its right (125, 155). The
#   tale string writes it once, after }, and CommonEnding holds it, a
#   sibling of the moves it closes, so the tree says it belongs to them
#   jointly. CAVEAT: the grammar checks that the ending fits the tale's
#   last move; that it fits the other sharer is checked at the move level,
#   where each sharer is parsed with the ending unfolded.
#   METHOD 6: two seekers "part in the middle of the first move ... at a
#   road marker", designated <, and "often give one another an object: a
#   signaller", designated Y (pp.93-94; tale 155, whose scheme Propp
#   writes "I-II. <Y" with III and IV after it). Parting holds the marker,
#   the signaller if there is one, and the two branch moves.
# The glyphs < Y } are Propp's own. After the first move, either more
# moves follow in sequence or a parting does; after two or more moves, or
# after the branches, a common ending may close the tale. One token
# decides each choice, so the grammar stays LL(1).
# Method 4, two villainies at once, is not built: its two A-K spans cross,
# and no corpus case has been identified.

LaterMoves          = [ moveBoundary move {moveBoundary move}
                        [Parting] [CommonEnding]
                      | Parting [CommonEnding] ]

Parting             = roadMarker [signaller] move moveBoundary move
                                            # pp.93-94, method 6

CommonEnding        = commonEnding AfterLiquidation
                                            # p.93, method 5

moveBoundary        = '/'                   # editorial: one row per move,
                                            #   as in Appendix III

interruptionBegins  = '⟨'                   # editorial: where Propp prints
interruptionEnds    = '⟩'                   #   <N>, move N stands here
roadMarker          = '<'                   # Propp's sign, p.93
signaller           = 'Y'                   # Propp's sign, p.94
commonEnding        = '}'                   # Propp's closing brace, as
                                            #   drawn in 125 and 155

preparatorySection  = {absentation} interdictionViolation
                      reconnaissanceDelivery trickeryComplicity
                                            # Appendix I Table II, p.121, is
                                            #   titled The Preparatory
                                            #   Section; p.80 writes it as
                                            #   (β, γ-δ, ε-ζ, η-θ)

interdictionViolation
                    = [ interdiction {interdiction} {absentation} ]
                      {violation}           # p.80 γ-δ; p.64's pairs list,
                                            #   prohibition-violation.
                                            #   An absentation may be told
                                            #   after the interdiction:
                                            #   p.26 says the tale
                                            #   generally tells it first,
                                            #   and both whole tales Propp
                                            #   analyzes in Ch. IX tell it
                                            #   after, 113 at pp.96-97 and
                                            #   the wolf and the kids at
                                            #   p.101. The second place
                                            #   opens only after an
                                            #   interdiction, so a lone
                                            #   absentation has one place
                                            #   and the production stays
                                            #   LL(1). v43's RuleViolation.

reconnaissanceDelivery
                    = {reconnaissance} {delivery}
                                            # p.80 ε-ζ; p.64's pairs list.
                                            #   v43's InformationGathering.

trickeryComplicity  = {trickery} {preliminaryMisfortune} {complicity}
                                            # p.80 η-θ. λ is inserted on
                                            #   Table II item 44's wording,
                                            #   which confines the
                                            #   preliminary misfortune to
                                            #   the deceptive agreement.
                                            #   v43's DeceptionTrap.

# The preparatory section is borrowed whole from the first project's
# ProppMidLevelGroupsEbnf.txt, whose preparatoryGroup it accepts string
# for string; only the names differ.


# ----------------------------------------------------------------------------
# THE MOVE
# ----------------------------------------------------------------------------
# p.92: a move is any development proceeding from villainy or lack,
# through intermediary functions, to a denouement.
#
# THE MOVE TYPE IS DECIDED AT MoveOpener, NOT AT THE ROOT, by the owner's
# decision. v43 splits at the root, move = VillainyMove | LackMove, and
# that was considered and set aside for one reason: Propp names exactly
# one group in this span, the complication, "(ABC↑)" at pp.64-65, and a
# root split would have to copy it, and the arc containing it, once per
# opener, since a context-free grammar cannot pass the opener down to a
# shared production. With the choice at MoveOpener, the type is still
# read off every tree, as the child of MoveOpener, and the complication
# is one production. The root-split form accepts the same strings and is
# equally LL(1) at its top, so nothing but the tree's shape rides on the
# choice.
#
# T STANDS ANYWHERE (step 3). p.108: T is "the most unstable function in
# relation to its position"; its most appropriate places are before or
# after the punishment, or before the wedding, where it is most often
# found. By the owner's decision T may stand at any position in a move,
# before its opener included, and it has no slot of its own. FloatingT
# leads every move and Between follows every function, so any run of T's
# between two functions, or before the opener, has exactly one place to
# go, and no LL(1) conflict arises. WHERE A T HANGS IN THE TREE IS WHERE
# THE PARSER MEETS IT, NOT A GROUPING: attaching a T to the function before
# it claims nothing about Propp.
#
# A MOVE MAY PAUSE FOR ANOTHER MOVE (step 7). p.93: "a development which
# has begun pauses, and a new move is inserted" (method 2), and "an
# episode may also be interrupted in its turn" (method 3). Ch. IX n.4
# designates the interruption by dots with an indication of which move
# breaks the thread. Between, the slot after every function, holds a T or
# an InterruptingMove; FloatingT, before the opener, holds only a T, since
# nothing pauses before it has begun. The inserted move is a full move, so
# a move can hold a move to any depth, and THE GRAMMAR IS NO LONGER
# REGULAR: move refers to itself through InterruptingMove.
# IT STAYS LL(1). The inserted move is bracketed by its own markers, ⟨ and
# ⟩, so one token shows where it begins and where the interrupted move
# resumes (finding FO point 4). The markers are this grammar's, not
# Propp's: his < is the road marker of method 6. Where he prints <III> in
# a move's row, the tale string carries move III itself, bracketed, at that
# point (embedCorpus.py).
# WITH InterruptingMove REMOVED, THE GRAMMAR IS EXACTLY STEP 6'S, which
# equivCheck.py proves with --drop-b InterruptingMove.

move                = CrisisToLiquidation AfterLiquidation

FloatingT           = {transfiguration}     # p.108; before the opener only

Between             = { transfiguration | InterruptingMove }
                                            # p.108 for T; p.93 for the
                                            #   pause. Editorial name.

InterruptingMove    = interruptionBegins move interruptionEnds
                                            # p.93 methods 2 and 3;
                                            #   Ch. IX n.4


# --- from the crisis to its liquidation: the A-K pair as a constituent ---
# p.53: liquidation "together with villainy (A), constitutes a pair".
# Finding FP: a distant pair can be a constituent one level up, its middle
# being the groups that fall between. The span also covers a lack and its
# liquidation, and a continuation move opened on B.
#
# J-Q IS NOT A CONSTITUENT, AND CANNOT BE IN THE SAME TREE. Branding (J,
# XVII) falls inside this span and recognition (Q, XXVII) outside it, so
# the two spans cross (finding FP). J-Q is carried as a dependency only:
# the J in Combat marks the hero whom the Q in Endgame recognizes.

CrisisToLiquidation = complication Development {liquidation Between}

complication        = FloatingT MoveOpener Between
                      {mediation Between}
                      {beginningCounteraction Between}
                      [UntestedAcquisition]
                      [ departure Between {departure Between}
                        [UntestedAcquisition] ]
                                            # pp.64-65: villainy, dispatch,
                                            #   decision for counteraction
                                            #   and departure "(ABC↑),
                                            #   constitute the complication"

# --- the agent, tested or untested (step 6) ---
# EVERY F IS ONE OF TWO KINDS, AND THE TOKEN BEFORE IT SAYS WHICH. An F
# that follows the donor's test, D or E, is the TESTED agent, the reward
# of the donor episode, in Propp's DEF group (p.65). Every other F is the
# UNTESTED agent, received with no test: the father's gift before the
# departure, "cudgels, ropes, maces, and so forth, given by the father"
# (p.108), or an agent that comes to hand on the road with no donor.
# v43 names the two TestedAcquisition and UntestedAcquisition.
#
# WHY THE GROUPS ARE DRAWN HERE. Step 4 split the F's by whether a
# departure followed a run of them, the father's agent against the
# donor's. No lookahead can see past a run of any length, so that split
# cost an LL(1) conflict on F. The owner chose to merge (step 6). With
# the split drawn at the test instead, the D or E before an F decides its
# group, and the grammar is LL(1).
#
# WHAT THE TREE NOW SAYS. The untested agent belongs to the setting out:
# it stands inside the complication, before the departure and, once a
# departure has been read, after it, which is the only place one token
# can assign it. Propp's complication, ABC↑, thereby holds an optional
# untested agent on either side of the ↑. The tested agent belongs to the
# donor episode, in Development.
#
# WHAT IT COSTS. The language widens: an untested agent may be followed
# by a test, as in A F D E, which step 4's narrow reading of p.108
# refused. No page licenses it and none forbids it. Keeping the narrow
# reading with LL(1) would mean taking ↑ out of the complication, which
# is the one group in this span Propp names.

UntestedAcquisition = receiptOfMagicalAgent Between
                      {receiptOfMagicalAgent Between}
                                            # p.108; v43's name

MoveOpener          = villainy              # p.92
                    | lack                  # p.92
                    | mediation             # p.37: where no villainy
                                            #   occurs, the connective
                                            #   incident opens the move
                                            #   (133 II)

Development         = [TestedAcquisition] {spatialTransference Between}
                      Combat

TestedAcquisition   = firstDonorFunction Between
                      {firstDonorFunction Between}
                      {heroReaction Between}
                      {receiptOfMagicalAgent Between}
                    | heroReaction Between
                      {heroReaction Between}
                      {receiptOfMagicalAgent Between}
                                            # p.65: DEF "also form something
                                            #   of a whole". v43's name;
                                            #   before step 6, Vetting.
                                            #   It opens on the test, D,
                                            #   or on the hero's reaction,
                                            #   E, when D is omitted.

Combat              = {struggle Between}
                      {branding Between}
                      {victory Between}   # p.104, the struggle scheme
                                            #   H J I; H-I a pair, p.64


# --- after the liquidation ---
# The span after K has no name in Propp. Its groups are v43's names over
# v44's order; v43's obligations are not carried, every function staying
# optional and repeatable as in v44.

AfterLiquidation    = ReturnJourney Ordeal Endgame

ReturnJourney       = {return Between} Evasion
                                            # v43's name

Evasion             = [ PursuitFirst | RescueFirst ]
                                            # pursuit-rescue, a pair in
                                            #   p.64's list. v43's name.

# --- two licenses on the pursuit (step 4) ---
# p.107: "In tales 93 and 159 the fight with the villain takes place
# only after pursuit." CombatAfterPursuit lets the struggle group stand
# after a pursuit, and only after one.
# p.147, on tale 150: "Humorous inversion: the villain runs away instead
# of the hero; the hero pursues [Rs-Pr]." RescueFirst lets the rescue
# precede the pursuit. Built into the grammar, it holds for every tale,
# not only the humorous ones Propp names: that is the cost of
# internalizing a license, and the page is its defense.
# The two openings differ in their first symbol, so the choice between
# them adds no conflict. CombatAfterPursuit's J is reachable only after a
# pursuit, and since step 5 the task-run J only after a task, so its J
# conflicts with neither.

PursuitFirst        = pursuit Between {pursuit Between}
                      {rescue Between}
                      CombatAfterPursuit

RescueFirst         = rescue Between {rescue Between}
                      [ pursuit Between {pursuit Between}
                        CombatAfterPursuit ]

CombatAfterPursuit  = {struggle Between}
                      {branding Between}
                      {victory Between}   # p.107; H J I as in Combat

Ordeal              = FraudPosture TaskCycle
                                            # v43's name, less its closing
                                            #   recognition, which now
                                            #   exchanges in Endgame. No
                                            #   page groups these; for
                                            #   reading only.

FraudPosture        = {unrecognizedArrival Between}
                      {unfoundedClaims Between}
                                            # v43's name; o and L shift
                                            #   between the two summed
                                            #   schemes together, p.104

TaskCycle           = [ difficultTask Between {difficultTask Between}
                        {branding Between} ]
                      {solution Between}  # p.104, the task scheme M J N,
                                            #   set in the position H J I
                                            #   holds in the other. p.64's
                                            #   pairs list does not name
                                            #   M-N. v43's name.

# THE TASK-RUN J COMES ONLY AFTER A TASK (step 5). Before step 5 the
# second J slot was reachable with no M before it, so A J N parsed two
# ways, the fight's branding then a solution or the task run J N, and a
# J after the fight could not be assigned by one token of lookahead. That
# was the J conflict. v44's own comment names this repair,
# { 'M' {'J'} } {'N'}, and calls K J and Pr Rs J over-generation Propp
# licenses in neither place; it was held back only because falsify44.py
# could not read nested productions. A J with no task before it is now
# the fight's, in Combat or CombatAfterPursuit, or out of order. The
# solution still stands without a task, as the preliminary solution *N
# does (commentary p.145).

# --- the endgame: p.108's exchange (step 3) ---
# p.108: "Recognition and exposure, marriage and punishment may also
# exchange positions." On FN's reading, the one the first project has
# always used, the four exchange among themselves, so they share one
# repetition in any order: 139 II's U Q W is accepted. On the narrow
# reading, swaps only within each named pair, U Q W would be refused.
#
# THE STEP 2 GROUPS IdentityReveal (Q Ex) AND Resolution (U W) ARE GONE.
# Once U Q W is admitted, recognition can stand between punishment and
# wedding, so the two pairs are no longer contiguous in every tale and
# cannot both be constituents. Endgame is v44's own word for this span.

Endgame             = { ( recognition       # XXVII
                        | exposure          # XXVIII
                        | punishment        # XXX
                        | wedding           # XXXI
                        ) Between }
